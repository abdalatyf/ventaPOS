# VentaPOS Ecosystem Architecture (Current State)

This document outlines the global state of the VentaPOS ecosystem architecture, serving as a permanent memory for all agents regarding features that are operational, disconnected, or currently under development.

## Ecosystem Overview (Offline First)
The VentaPOS ecosystem is currently operating as a strictly offline, locally installed suite of tools. The centralized cloud components exist but are either separate or under construction.

## 1. Desktop & LicenseManager (Core Operations)
**Status:** Operational & Offline Only

*   The **Desktop** application is the primary Point of Sale. It runs entirely offline using a local SQLite database (`business_data.enc`).
*   It is activated strictly via an offline license key generated by the standalone **LicenseManager** Django portal. The client inputs their `machine_id`, gets a cryptographic string, and inputs it into the Desktop app which mathematically verifies it.

## 2. Mobile ↔ Desktop (Air-Gapped Sync)
**Status:** Incomplete (Desktop Import Pending)

*   The **Mobile** application operates 100% offline. It allows salespeople to create receipts locally and exports this data as a JSON file (`Sales_B{...}.json`).
*   **Missing Link:** The feature inside the Desktop application designed to ingest and parse this exported Mobile JSON file is **not yet completed**. Currently, there is a disconnect between mobile data collection and desktop centralization.

## 3. Server Backend (Cloud Synchronization)
**Status:** Not Done Yet (Future Roadmap)

*   The **Server** is designed to provide an "online option" for centralizing data across multiple branches, but it is currently non-operational or incomplete in the current flow.

## 4. Promo Website
**Status:** Separated

*   The **Promo** website is strictly for marketing purposes. It operates independently and has no data or API connections to the POS ecosystem.
